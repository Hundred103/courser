
!!!!!!!!!!!!!!!KONTENERY MUSZA CHODZIC!!!!!!!!!!!!!!!

Wymagania: Docker z wtyczką Compose v2 (`docker compose`, nie `docker-compose`).

---URUCHOMIENIE / RESET BAZY (z katalogu głównego repo)---
docker compose down
docker volume rm courser-postgres-data
docker compose up -d

Usługi quiz-service i user-service startują dopiero po pomyślnym zakończeniu Liquibase
(`depends_on: service_completed_successfully`). `docker compose up -d --wait` czeka wyłącznie
na serwisy ze zdefiniowanym healthcheckiem (obecnie PostgreSQL) — nie polegaj na nim jako
gwarancji zakończenia migracji Liquibase.

Sprawdzenie statusu migracji:
docker compose ps -a liquibase
docker inspect -f '{{ .State.ExitCode }}' courser-liquibase

Liquibase utworzy schemat i dane startowe (kontekst `seed`).

---RĘCZNE URUCHOMIENIE LIQUIBASE (lokalnie, bez Dockera)---
Wymaga zainstalowanego Liquibase CLI oraz działającego PostgreSQL na porcie 5433:

cd postgre/liquibase
liquibase --defaults-file=liquibase.properties update

Tylko schemat (bez danych startowych):
liquibase --defaults-file=liquibase.properties --contexts="" update

---RĘCZNY IMPORT dump.sql (legacy, opcjonalnie)---
(Linux/Mac):
docker exec -i courser-postgres psql -U courseruser -d courserdb < postgre/dump.sql

(Windows PowerShell):
Get-Content .\postgre\dump.sql | docker exec -i courser-postgres psql -U courseruser -d courserdb

Jeżeli chcesz wyczyścić schemat przed importem:
docker exec -it courser-postgres psql -U courseruser -d courserdb -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"

---EXPORT (zrzut istniejącej bazy)---
(Linux/Mac):
docker exec courser-postgres pg_dump --encoding=UTF8 -U courseruser -d courserdb > postgre/dump.sql

(Windows cmd):
cmd /c "docker exec courser-postgres pg_dump --encoding=UTF8 -U courseruser -d courserdb > postgre\dump.sql"

---UWAGI DLA USŁUG (quiz-service i user-service)---
- Schemat bazy jest zarządzany przez Liquibase (katalog `postgre/liquibase/changelog/`).
- Obie usługi korzystają z tej samej bazy `courserdb` (użytkownik `courseruser`).
- Hibernate `ddl-auto` jest ustawione na `validate` — zmiany schematu wprowadzaj wyłącznie przez Liquibase.
- Nowe migracje dodawaj jako pliki w `postgre/liquibase/changelog/changes/` i dołącz je w `db.changelog-master.yaml`.
